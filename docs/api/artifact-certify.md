# artifact.certify

> Certify the Forge NormalizedVizSpec returned by viz.render. Returns coverage, a measured conformant result, findings, and four pillars: a11yEquivalence, determinism, contrast and accuracy. Read-only: it reads the IR and the matching data operand without rebuilding or recommending a chart.

DECLARED COVERAGE. The five Cartesian types certify from the IR alone. The eight ECharts-primary types certify under the declared operand profile when the same data branch used by viz.render is supplied. ECharts conformance requires a11yEquivalence:'pass', contrast neither 'fail' nor 'ungradeable', stable determinism, and accuracy:'pass' with rulesEvaluated > 0 and no detected distortion. A certified chart can be conformant:false; inspect the pillars and findings. No Vega-Lite compile is added to the ECharts profile. Spec-only ECharts calls remain coverage:'uncertified' with conformant:null and notes naming the missing operand. Unmodeled marks remain explicitly uncertified.

DATA. An ECharts-primary IR carries metadata; nodes, links, rows and geometry live in its original branch. Supply exactly the matching hierarchy, sankey, chord, network or geo branch as data. The tool validates it against the mark trait. Data on a Cartesian IR is OODS-V123 because those charts certify from their IR. HTML or invalid IR is OODS-V126.

ACCESSIBILITY. The 16 equivalence rules evaluate the operand-built table and narrative. Error-severity failures fail the ECharts pillar and conformance. Warnings stay visible without failing the pillar. Findings keep their native severity. a11yNotApplicable lists rules whose declared preconditions were absent; absence is not a meaningful pass. This channel is present when the ECharts engine completed, including [] if no rule was inapplicable, and absent for spec-only, Cartesian or incomplete engine evaluations. A completed engine with an individual rule fault retains its findings and not-applicable results while failing the pillar. An evaluator fault cannot produce a passing accessibility pillar.

ACCURACY. Cartesian rules read the IR and compiled spec: non-zero bar baseline (V150), dual axis (V151), area scaling (V152), undisclosed aggregation (V153). ECharts rules read data: invalid hierarchy values/non-additive parents (V154/V155); invalid sankey/chord link values (V156); inconsistent sankey node throughput/duplicate links (V157/V158); conflicting choropleth join values (V159); negative or non-finite bubble size (OODS-V168), radius-based bubble scaling (OODS-V169), conflicting rows at the same bubble coordinates (OODS-V170), negative or non-finite flow strength (OODS-V171), duplicate directed geographic flows (OODS-V172), and duplicate directed force-graph links (OODS-V173). Reciprocal graph links and reciprocal geographic flows are distinct. Bubble scaling reads the public renderer's default linear size behavior; certification does not repair its pixels. accuracyRules lists offered codes, while accuracySummary counts only rules whose preconditions resolved. Pass means no offered rule detected its distortion, not a general promise of accuracy; zero evaluated ECharts rules is unchecked and cannot yield conformant:true.

DETERMINISM. Two independent compiler/adapter emissions are compared and rendered independently. contentHash identifies the first canonical compiled spec or projected ECharts option; renderHash identifies its normalized SVG and matches viz.render for the same operand/scope. Stable requires both identities to repeat. A first-render fault keeps contentHash, omits renderHash and fails stability. A bubble_map without inline geometry keeps the option proof, omits renderHash and names the no-server-map limitation. Proof is bounded by packages/viz-render/certified-matrix.json and covers certify's own rendering, not a caller's rendering.

CONTRAST. Cartesian charts and ECharts calls with data grade actual rendered paints. Role C checks mark-to-canvas WCAG 3:1; Role A checks categorical CIEDE2000 distinguishability across normal vision and three CVD simulations, retaining recycled-palette duplicates. Missing baked OODS palette bytes cannot produce contrast:'pass'. The three geo families retain the standing contrast exemption with their render evidence; this includes ordinal bubble maps. Spec-only ECharts calls retain the reconstructed palette grade and caveat. Cartesian conformance still fails for fail or ungradeable contrast/accuracy; unchecked and exempt retain their existing semantics. Read every pillar's enum, including ungradeable. contrastResults reports the requested theme/brand and measurement evidence; exemptions do not claim a canvas ratio.

SCOPE. Theme light|dark|hc and brand A|B select the same CSS scope as rendering, default light/A. HC contrast returns exempt, measured:false and reason:forced-colors, with no numeric grade. Accessibility, accuracy and determinism retain their normal evaluation; an actual HC render failure fails determinism and conformance. All 13 chart types render and certify conformantly in the 78 measured light/dark/HC and A/B scopes; HC has forced-colors browser proof and no numeric contrast grade. After a release that changes a schema or verdict, reconnect clients that cache tool descriptions and schemas.

**Registration:** auto

## Input Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `spec` | object | Yes |  | A Forge NormalizedVizSpec intermediate representation — the same IR viz.render emits as normalizedSpec. Validated authoritatively by the handler's assertNormalizedVizSpec. |
| `data` | object | No |  | OPTIONAL operand for the 8 ECharts-primary types (treemap/sunburst/sankey/force_graph/choropleth/bubble_map/flow_map/chord): the SAME data branch viz.render takes, so certify re-emits the option the render path would emit for this (spec, data) pair. EXACTLY ONE branch, and it must be the branch the IR's mark trait requires (MarkTreemap/MarkSunburst -> hierarchy, MarkSankey -> sankey, MarkChord -> chord, MarkGraph -> network, MarkChoropleth/MarkBubble/MarkFlow -> geo); a mismatch is a structured error. Supplying `data` alongside a CARTESIAN IR (MarkBar/MarkLine/MarkPoint/MarkArea/MarkRect) or an unmodeled mark is also a structured error — those paths compile from the IR itself, so the operand would be dead input. Omitting `data` is always valid: the verdict is then the pre-s172 one with determinism and accuracy honestly 'unchecked' and a note saying why. |
| `data.hierarchy` | _ref_ | No |  |  |
| `data.sankey` | _ref_ | No |  |  |
| `data.chord` | _ref_ | No |  |  |
| `data.network` | _ref_ | No |  |  |
| `data.geo` | _ref_ | No |  |  |
| `theme` | `light` \| `dark` \| `hc` | No | `"light"` | CSS token theme for chart pixels, default light. HC emits the declared scope colors verbatim, including CSS system colors; their computed paints require a forced-colors browser. A renderer that substitutes undeclared paints is typed-deferred instead of returning misleading HC pixels. No server-side system-color hex palette is invented. |
| `brand` | `A` \| `B` | No | `"A"` | CSS brand scope, matching viz.render for the same normalized spec and data operand. |

## Output Shape

| Field | Type | Always Present | Description |
|-------|------|----------------|-------------|
| `status` | `ok` \| `error` | Yes | Whether certification ran. 'error' means the input was not a valid NormalizedVizSpec IR. |
| `coverage` | `certified` \| `uncertified` | No | Certified identifies the Cartesian or declared ECharts data-operand profile, not a passing result: read conformant and the pillars. Uncertified identifies a spec-only ECharts call or an unmodeled mark. Spec-only ECharts contrast may still be reconstructed or exempt, while data-dependent a11y, determinism and accuracy remain unchecked. Absent on error. |
| `conformant` | boolean \| null | No | Boolean for a certified profile; null for uncertified calls; absent on error. The ECharts operand profile is true only when a11y-equivalence passes, determinism is stable, contrast is neither fail nor ungradeable, and accuracy passes with rulesEvaluated greater than zero and no accuracy findings. Error-severity a11y findings and evaluation faults fail that pillar; ordinary warning findings and not-applicable rules do not. Cartesian behavior is unchanged: its four pillars fold together, with contrast/accuracy fail or ungradeable preventing conformance. Accuracy unchecked cannot pass the operand profile. A measured false is retained, never converted into uncertified. |
| `findings` | _ref_[] | No | One entry per failing a11y-equivalence or accuracy rule, at native severity. A11y codes use OODS-A11Y-<rule.id>; accuracy codes use their registered OODS-V codes. Warnings remain visible without failing a11y, while error-severity a11y findings and any accuracy findings prevent operand conformance. An evaluator fault is reported separately in the pillar and notes, so empty findings alone never imply a pass. |
| `a11yNotApplicable` | object[] | No | One entry per a11y-equivalence rule whose declared precondition was absent, in rule order with the precondition named. Present, possibly empty, when the ECharts operand engine returns the complete rule population; absent without data, on Cartesian calls, on tool error, or when the engine throws or returns an incomplete population. An individual rule evaluator fault retains the completed engine population and native findings, while failing the a11y pillar. Not-applicable rules never enter findings and are not counted as failures. |
| `accuracySummary` | object | No | How the accuracy pillar was reached. Present when rules completed: on Cartesian calls and ECharts calls with data. Absent without an ECharts operand or on an evaluator fault. rulesEvaluated counts resolved rule operands; a rule whose precondition is absent is not counted and explains why in notes. The ECharts operand profile requires at least one evaluated rule and zero failing rules. |
| `determinism` | object | No | Re-emit and render determinism proof. Cartesian results identify the canonical Vega-Lite compile with contentHash and, when rendering occurred, the first normalized SVG with renderHash. ECharts-primary results are present when the `data` operand was supplied: contentHash identifies the retained projected option, and renderHash is present whenever that projected option was rendered successfully. In both families `stable` folds two independent emissions and, when renderHash is present, two independent normalized renders. A typed first-render fault keeps contentHash, omits renderHash, and makes stable false; bubble_map without inline geometry keeps the option proof and names the no-server-map limitation. Absent on the error path and on an ECharts verdict with no operand. |
| `pillars` | object | No | Per-pillar verdicts on successful tool responses, including nonconformant results. Data-backed ECharts calls grade a11y over the shared operand-built table/narrative, repeat option emission and available rendering for determinism, measure or exempt contrast, and run the per-type accuracy rules. Spec-only ECharts calls keep data-dependent pillars unchecked and retain legacy contrast behavior. A fault cannot silently produce a passing profile. |
| `contrastNote` | string | No | Contrast rationale naming the exact theme/brand. Cartesian and data-backed categorical ECharts results grade rendered paints against that CSS scope canvas; geo and continuous heatmap results remain exempt. Spec-only ECharts calls reconstruct scoped baked colors and make no rendered-carrier measurement claim. For exempt results, no canvas ratio is graded. |
| `notes` | string[] | No | Path-specific scope and missing-operand explanations, runtime-matrix limits, unmet rule preconditions and evaluator faults. The operand note describes the enforced profile; the spec-only note explains why coverage remains uncertified and conformant null. Empty offered/resolved rule sets remain explicit and cannot pass the operand profile. |
| `errors` | _ref_[] | No | Present and non-empty when status is 'error' (the input was not a valid NormalizedVizSpec IR). |
| `contrastResults` | object[] | No | The contrast row for this call's requested theme/brand. Collect rows from separate scope calls to compare themes. measured is true only for a successful render-backed categorical evaluation (pass or fail); exempt, unchecked, ungradeable and spec-only palette reconstruction do not claim a completed canvas ratio measurement. |
| `accuracyRules` | `OODS-V150` \| `OODS-V151` \| `OODS-V152` \| `OODS-V153` \| `OODS-V154` \| `OODS-V155` \| `OODS-V156` \| `OODS-V157` \| `OODS-V158` \| `OODS-V159` \| `OODS-V168` \| `OODS-V169` \| `OODS-V170` \| `OODS-V171` \| `OODS-V172` \| `OODS-V173`[] | No | Offered accuracy rule codes for this chart type. This closed set is distinct from accuracySummary.rulesEvaluated, which counts resolved operands; an empty array means no rule is offered. |
