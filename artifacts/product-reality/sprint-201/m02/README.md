# s201-m02 — Compositions with versions and lineage

## What is in the tree

- **Composition store** (`packages/mcp-server/src/lib/composition-store.ts`): `<schema store>/../compositions/<compositionId>/versions/<n>.json`. A version holds the compose inputs (replayable), the schema and its hash, the parent version, the operation (`compose`, `recompose`; m05 adds the four edits), the Forge head (`build-revision.json`), the brand and theme it was generated for, the slot leaders, and what `design.preview` attaches: the deterministic model and the generated artifact per framework (`measurements` is m04's). Ids are `cmp-` plus twelve hex characters (`OODS-V203` for anything else); versions are written once (`wx`) so no operation ever overwrites a schema; `attachToVersion` replaces the file atomically with the schema asserted unchanged; an unknown composition or version is `OODS-N022`.
- **`design.compose` records every successful composition** as version 1 of a new composition, or with `compositionId` (and optional `parentVersion`) as the next version with operation `recompose`; the result carries `compositionId`, `version`, `parentVersion`, `operation`, `head` beside the unchanged `schemaRef`. `options.transient` records nothing (the preview's workflow seed composition uses it).
- **One URL per version** in the preview host: `/preview/<id>/<n>?framework=&brand=&theme=&width=` is the page with the lineage panel (composition, version of N, parent link, operation, Forge head, schema hash, created, generated-for) and the version list, framing the running app; `/preview/<id>/<n>/app` is the bare app; `/preview/<id>` redirects to the latest; `/preview/<id>/versions.json` lists versions; `module.js`, `record.json` and `files/*` as in m01. The m01 schema-hash records are gone.
- **Brand and theme are switches**: the page posts `oods-preview-scope` to the framed app, which sets `data-brand`/`data-theme` on its document and body and re-mounts the same module (React root unmount/render, Vue app unmount/mount) without fetching anything again; the page URL follows the switch. The single stylesheet carries every brand × theme scope. The framed app reports `generatedFor` (the scope its inline chart SVG was rendered in), so a switch never claims the chart re-rendered.
- **Width is a control**: 390 / 820 / 1440 and free (200–3840); the framed app's viewport is the chosen width.
- **`design.preview`** takes `compositionId` (+ optional `version`) or `object` + `context` (composed now as a new composition), reuses artifacts a version already carries, and returns `compositionId`, `version`, `parentVersion`, `operation`, `head`, `object`, `context`, `previewUrl`, `previews[]` with `url` (lineage page), `appUrl`, `moduleUrl` and the compiled digests. Contract regenerated: schemas, types, `docs/api`, `Tool-Specs.md` (122 root input parameters), claims, the runbook persistence row, tool descriptions and the agent policy.
