## What is in the tree

- **Preview host in the bridge** (`packages/mcp-bridge/src/preview/`): `/preview/status`, `/preview/<key>?framework=react|vue&brand=A|B&theme=light|dark|hc`, `/preview/<key>/module.js`, `/preview/<key>/record.json`, `/preview/<key>/files/*`, `/preview/runtime/*`. Each generated artifact is compiled at request time into one ES module with esbuild (TSX) and `@vue/compiler-sfc` + esbuild (SFC), cached by the artifact's content hash; bare imports stay external and resolve through the page's import map. A compile failure answers 422 with the file and line; a missing or partial runtime refuses registration.
- **Prebuilt host runtime** (`packages/mcp-bridge/scripts/build-preview-runtime.mjs`, run by the package build): `dist/preview-runtime/` holds React, ReactDOM, Vue, the foundation packages' dist and the component-styles + token CSS as ES modules that share one React and one Vue instance (esbuild splitting; CommonJS packages get explicit named re-export shims), plus `manifest.json` with every file's size and digest. 19 files, 1,667,404 bytes.
- **The page** (`page.ts`) mounts the artifact as `scripts/design-loop/serve.ts` `consumerEntries` does: `data-theme`/`data-brand` on the document and body, the deterministic field model as props, every required action dispatching `oods-design-loop-action`; it publishes `window.__oodsPreview` and `data-oods-preview-mounted` once mounted.
- **`design.preview` rewritten** (`packages/mcp-server/src/tools/design.preview.ts`): composes, generates one or both frameworks, seeds the model with the design loop's policy (moved into `codegen/preview-model.ts`; the loop imports it back), writes one record per schema hash beside the saved-schema store (`lib/preview-store.ts`, `.oods/previews/<key>.json`), asks the host to compile each framework, and returns one URL per framework with the compiled digests. Input drops `widths` and gains `preferences.brand` and the `hc` theme; output is the URL set. `OODS-N019` is retired; an unreachable host, a host on another store root, or a platform without a bundled binary returns retryable `OODS-N021`.
- **Host address per request**: the stdio envelope gains an optional `context.previewHostUrl` (`lib/tool-context.ts`); the bridge sends its own address, the adapter the host it started; `OODS_PREVIEW_HOST_URL` remains for a native server run on its own.
- **Adapter 0.4.0** (`packages/mcp-adapter/index.js`): starts `packages/mcp-bridge/dist/preview/standalone.js` on 127.0.0.1 at a free port the first time `design_preview` is called, reads the port from the host's one stdout line, logs `preview host started on …` to stderr, keeps stdout for JSON-RPC, reuses the host for later calls and stops it with the adapter.
- **Closure**: `@oods/mcp-bridge` depends on esbuild `0.25.10` with `@esbuild/darwin-arm64`, `darwin-x64`, `linux-arm64`, `linux-x64` as plain dependencies, `@vue/compiler-sfc`, react, react-dom, vue and the five foundation packages; the host pins the shipped binary through `ESBUILD_BINARY_PATH` before esbuild loads. The SBOM records a normalized `platformSpecific` marker (pnpm's post-install lock drops `cpu`) and asserts the platform-bound packages are exactly the four binaries; the assembler asserts each binary exists and the bridge resolves all four, and allows the bundled component-contracts provenance string. Closure 283 → 314 packages; `THIRD-PARTY-NOTICES.md` and `install.md` (with the platform matrix) regenerated.
