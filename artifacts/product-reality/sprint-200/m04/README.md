## What is in the tree

- **Third-party notices, generated.** `scripts/runtime/third-party-notices.mjs` (with `--check`) walks the same pnpm-lock closure `runtime-sbom-lite.json` records, resolves every package in the repository's virtual store, and writes `THIRD-PARTY-NOTICES.md`: 283 entries with the declared SPDX identifier, the project URL and the shipped license text (four packages publish none and are listed as such). The header carries the lockfile sha256, so a stale file is detectable, and the assembler refuses to run when the file is stale.
- **The terms in the archive.** `assemble.mjs` copies `LICENSE`, `COMMERCIAL.md` and `THIRD-PARTY-NOTICES.md` into the archive root through the tracked boundary (`TERMS_FILES` in `scripts/runtime/manifest.mjs`, the same roster `scripts/pkg/build.ts` ships beside `dist/pkg`); the manifest records each file's sha256 under `terms`; `verifyEmbeddedManifest` and the E2E assert the shipped bytes equal the manifest and the repository copies.
- **Brand source in the bundle.** `brand.apply` reads exactly one source subtree, `packages/tokens/src/tokens/brands/` (A and B × base/dark/hc); nothing else under `packages/tokens/src` is read by a bundle call, and the two token build stages are host-only by design (`canRunTokenBuild()` is false wherever `forge-runtime.manifest.json` exists). The assembler ships that subtree (`PACKAGE_RUNTIME_DIRECTORIES.tokens`), the manifest records its tree digest (`brandSourceTree`) and asserts it equals the repository's, and OODS-N020 no longer fires from the archive.
- **Portable `apply:true`.** From a runtime that cannot rebuild tokens, `brand.apply` with `apply:true` still emits the review kit (three applied theme snapshots, `specimens.json`, `variables.css`, `diagnostics.json`) under the policy run directory, skips the source write and the token build, and says so in the receipt (`sourceWritten:false`, `build:null`, `portable:{sourceWrites:"skipped",tokenBuild:"skipped",reason}`); the output schema admits the new block. The shipped brand source and dist stay byte-identical. The tool description, the ledger caveat, `docs/api`, `Tool-Specs.md`, the claims templates and both package READMEs say the same thing; OODS-N020 remains for a genuinely missing directory (the s196 specs that remove the directory still pass).
- **E2E from the archive.** `scripts/runtime/e2e.mjs` now asserts the terms files and the shipped brand directories, calls `brand.apply` twice (the pinned preview operand, then an apply of one brand-B colour) and proves the brand-source digest unchanged; 30 primary calls across the 19 tools, 31 across two adapter processes; 18 pass, 1 typed (`design.preview`, OODS-N019). Its registry, viz and catalog pins moved to the Sprint 199 head truths (110 components, 46 traits, 23 patterns, 36 classified, 17 core cells) and the assembler's tracked-boundary counts to 57 schemas, 78 traits and 41 structured-data files with the two Sprint 199 component snapshots in the provenance allowlist; the bundle had not been assembled since Sprint 196.
- **Ledger mode `s200`.** `s193-tool-truth.mjs` and `tool-ledger.ts` bind the portable execution to `artifacts/product-reality/sprint-200/m04/e2e-host.json` with one typed code; `brand.apply` is a `pass` row with no portable limit. The contract specs that pinned s196 literals (tool-truth, tool-specs generator, portable claims, how-forge-works, forge-claims) derive from the ledger instead.
- **Runbook rewritten.** `docs/runtime/portable-runtime.md` is the public contract: release assets, local build and verification (no hosted CI anywhere), what the archive contains, what it never contains, the runtime-relative roots, the tool surface with its one remaining typed limit, the E2E sequence, the persistence and environment contracts. `tests/verification/portable-runbook.s200.test.ts` asserts the absent words ("private handoff", "named consumers", "Gate 1", "Gate 2", "reconnect", "CI-15", "hosted CI"), the boundary sentences, the tool block in registry order, the closure count, the environment names, the generated install outputs and the freshness of the notices.
- **Aliases retired.** `./ported` and `./readiness-ported` left `@oods/components-react` and `@oods/components-vue`; `./ported` and `./css-ported` left `@oods/component-styles`; the envelope allowlist lost the three alias specifiers. The three package contract specs assert absence and `ERR_PACKAGE_PATH_NOT_EXPORTED`; the envelope test asserts a retired import is rejected; the packed-import scripts and the s184 packed-consumers generator prove the former eight families through the roots and record `retiredSubpaths`; `ported-workflow.s184` asserts the alias no longer resolves. Historical receipts are untouched. The readiness evidence `derivation` sentence records the retirement in both files; no live script writes that sentence, so it was edited in place. CHANGELOG carries the breaking entry.
- **Install path from one template.** `scripts/runtime/client-configs.mjs` (with `--check`) renders `docs/runtime/install.md` and `configs/agents/{claude-desktop,claude-code,cursor}.stdio-mcp.json` from one template with one placeholder (`/path/to/forge-runtime`), the server name `forge`, the tool counts from the registry, the adapter version and the Node floor from the packages. `docs/mcp/Connections.md` is the contributor (clone) path and links to `install.md`; `packages/mcp-adapter/test-s55-m05.js` pins the new snippets and the Claude Code config.
- **Clean-HOME Claude Code proof.** `scripts/product-reality/s200-claude-code-proof.mjs` creates a temporary HOME and scratch project, runs the documented `claude mcp add forge -- node <dir>/packages/mcp-adapter/index.js`, records `claude mcp get forge` (`Status: ✓ Connected`), reads back the stored registration and drives the adapter over stdio with exactly that command: initialize, `tools/list` (19 tools in registry order) and `health`; then removes the registration and the temporary HOME.
