## What is in the tree

- **The app** (`packages/mcp-bridge/preview-app/main.ts` and `index.html`, type-checked by `preview-app/tsconfig.json` in the bridge build) is one self-contained resource, `dist/preview-app/app.html`: **2,088,542 bytes**, revision `ac1689217541`. It holds the app script with the MCP Apps SDK 1.7.5 (416,703 bytes), the runtime a generated app runs on (`globalThis.__oodsRuntime`: React 19.2.0, ReactDOM, Vue 3.5.42 and the foundation packages; 1,504,459 bytes, sha256 `53116b779fa8a2dc…`; axe-core left out, descope rung 1) and the preview runtime's CSS (162,915 bytes). No CSP is declared and nothing loads from the network. From a `design_preview` result the app reads the version record and the lineage list through `resources/read`, then the compiled module and styles for the mounted framework, brand and theme; it injects the module as an inline script and mounts it as the Sprint 201 page does: the field model as props, every action dispatching `oods-design-loop-action`, React committed synchronously, Vue through `createApp`, a workflow artifact running its own mount. The scope goes on the document, as on the page (the runtime CSS resolves its `--sys-*` aliases on `:root`), and on the app's frame.
- **The panel** is the Sprint 201 page's: `renderLineage` and `renderVersionList`, extracted from `shell.ts` with the page's output byte-identical, where another version opens in place; and `renderMeasurementPanel`, which names every unrun scope. A note says axe runs in the browser page and this view shows what the version stored.
- **Switches** re-mount in the same document: framework, brand, theme and version. When the placed chart was rendered for another scope, the app first calls `design_preview` through the host (`tools/call` with `compositionId`, `version`, `framework` and `preferences: {brand, theme}`), which renders and certifies it for that scope, and then reads that module.
- **The host shapes the first view**: the host's theme is the initial theme unless the call named one; the host's style variables style the panel, never the running app; the app is as wide as the host's container (`containerDimensions`); the 390, 820 and 1440 controls fix the width; a width the container cannot show requests `fullscreen`, and `inline` is requested again when the width fits.
- **Widths inside a shared document**: the running app shares its document with the panel, so the build rewrites the runtime CSS's width-only media queries into `@container oods-app` queries answered by the app's frame (`(max-width: 40rem)` and `(max-width: 600px)` twice); the seven other media queries (forced colors, reduced motion) stay media queries. The manifest records both lists.
- **The build refuses** (`build-preview-app.mjs --runtime-dir`) before writing anything when the preview runtime's styles are missing.
- **Shared scope helpers**: `scopeKey`, `hasPlacedChart` and `servedArtifact` moved to the browser-safe `src/preview/scope.ts` (re-exported by `store.ts`), so the host and the app choose the same artifact.
- **Fixed on the way**: the root `pnpm typecheck` had failed since m02, because `s202-reference-host.ts` and `reference-host/host.ts` both declared `Window.__referenceHost`; the harness now types the page locally.
