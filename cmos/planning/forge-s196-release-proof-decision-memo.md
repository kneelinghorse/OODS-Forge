## 3. Settled decisions (build from these; do not reopen)

1. **The release artifact is the Gate-1 bundle with the bridge inside it.** `mcp-bridge` becomes the thirteenth runtime package in the same assembler; the publish boundary is unchanged (`packages/*` dist output; never `cmos/`, planning, brand source, tests or source `.ts`). From the extracted bundle the bridge starts from its own `dist/server.js`, spawns the bundled server, and serves `/health` (revision = the manifest commit, stamped at assembly from `forge-runtime.manifest.json`, never `git` at runtime), `/tools` (the 19 advertised names) and `/run`. `configs/agent/policy.json` enters the tracked boundary and the hard-coded `FALLBACK_POLICY` is removed: a bridge without its policy refuses to start with a typed error; there is no silent 20-tool roster. The static root resolves to the bundle's artifacts base; the runbook's environment contract gains `MCP_BRIDGE_PORT`, `BRIDGE_TOKEN`, `MCP_BRIDGE_CORS_ORIGIN`. The E2E proves the bridge from the extracted root on an ephemeral port: `/health`, `/tools`, one `viz.render` through `/run` whose `svgHash` equals the adapter path's for the same operand, and a clean stop. The three 245 assertions collapse into one derived pin re-measured at assembly (a declared mover with BEFORE/AFTER).
2. **The five portable limits are reconciled by category, never by adding source to the bundle.** (a) Declarations are dist: the pruner keeps `.d.ts` and `dist/ts/*.ts` and strips only `.map`, `.test.` and source `.ts`; readiness inside the bundle is proven by an assembly-time, hash-bound readiness attestation (one shipped registry file listing every readiness reference the host resolved, its sha256 and its evidence class, bound to the shipped package bytes) that the preflight verifies in place of reading source and test files — so `code.generate` and `pipeline` emit real React and Vue artifacts from the bundle. (b) `tokens.build apply:true` succeeds from the bundle because its outputs ship; a missing output in the bundle is a typed `OODS-N` code, never `OODS-S019` claiming a build ran. (c) `brand.apply` and `brand.intake` from the bundle return a new registered dependency-specific code ("canonical brand source is not shipped in this runtime") with the code at the wire — the boundary decision stands. (d) The adapter preserves structured native errors (code, retryable, data) through `tools/call`, so `design.preview` from the bundle returns `OODS-N019` with its code. After this the ledger's `portableLimits` shrink to two typed rows (`brand.apply`, `design.preview`), and the E2E asserts real success for `code.generate`, `pipeline` and `tokens.build apply:true`.
3. **The reference applications run from the bundle.** Subscription, Organization and User in React and Vue are generated by the bundle's `code.generate` through the adapter, installed against the bundle's own five packages (packed from the bundle's package directories, one pack per sweep, so the consumer sees exactly the shipped bytes), built and run in the pinned Playwright image with the existing gates: 42 cells (3 objects × 7 contexts including workflow × 2 frameworks). Every artifact generated from the bundle must equal the host sweep's artifact at the same head (`contentHash` equality; a difference is a finding, never tuned). The result is a generated `release-cells.v1.json` ledger served on host and portable health as `productReality.release {bundleHead, archiveSha256, apps, frameworks, cells, pass, typedGap, fail}`. The runtime ledger moves to a canonical path `packages/mcp-server/registry/runtime-cells.v1.json` written by the sweep; the server build stops copying from a sprint-numbered artifacts directory.
4. **Published claims are generated from the ledgers.** (a) `docs/components` is generated: one page per governed component (109) plus an index, from the component ledger (classification, nine surfaces with evidence), the authored contracts (`props`, `slots`, `events`, `states`, `tokenRoles`, `accessibility`), the catalog export (`contexts`, `regions`, `categories`, `tags`, trait usages) and the scenario count, with `--check`; the two legacy pages about governed components are superseded and the 31 pages about the Foundry-side tree move to `docs/history/components/` with a dated banner (retained, excluded from claims). (b) `docs/mcp/Tool-Specs.md` is generated from `tool-descriptions.json`, the input/output schemas (every top-level parameter, by construction), the tool ledger row (proof tier, portable outcome, documented limits) and an optional authored notes sidecar per tool (`docs/mcp/tool-notes/<tool>.md`) for policy and usage prose; the existing three gates keep passing; the stale line-260 snapshot becomes generated counts. (c) `docs/how-forge-works.html` keeps its prose but every numeric or roster claim lives in a marked span rewritten by a claims generator from the ledgers, registries and schemas with `--check`; the contract test pins every marked span and the set of claim keys; the unpinned numbers listed in §2 (41, 11/12, 38, "five outputs", "six cells", 31/10, "Thirteen", 16, the footer) become generated. (d) `docs/mcp/Connections.md` counts, `docs/README.md:61` and the README counts are generated or pinned; a `mcp-server` and `mcp-bridge` README are generated from the same sources. (e) One named CI step runs every doc `--check` (`docs:api`, taxonomy, pattern census, components, Tool-Specs, claims).
5. **Bites prove the gates bite.** Doc bites: a hand edit of each generated doc (`components`, `Tool-Specs`, the how-forge-works claims, `docs/api`) turns its `--check` red and a ledger count change turns it red until regenerated. Bundle bites: a byte change in a shipped dist file fails the manifest verification; a mutated bundled taxonomy degrades health and fails the E2E; a removed `policy.json` makes the bridge refuse to start; a tampered attested hash makes `code.generate` refuse from the bundle with a typed code. A cross-timezone bite: the same operand rendered under `TZ=America/Chicago` and `TZ=UTC` is byte-identical, and disabling the UTC pin makes them differ.
6. **Temporal axes render in UTC by construction.** Both adapters pin the timezone (Vega-Lite `utc` time units with `scale.type:'utc'`; ECharts `useUTC:true`), independent of the host; the declared rendering timezone is stated in the `viz.render` description, Tool-Specs and how-forge-works; the `scale-temporal` trait's `timezone` description moves to the truth (display-layer only, not consumed by the renderer) unless consuming it is trivial; host-locale number formatting (`toLocaleString()` without a locale) is pinned to an explicit locale. One-time golden migration for every temporal SVG golden and registry cell (line, area, running-total-area, the Usage line and Subscription area placements, temporal dashboard panels) with BEFORE/AFTER receipts; the four `America/Chicago` stubs are removed — the hashes must now hold under any host timezone.
7. **The gate-2 packet is prepared, not decided, and nothing is published.** `cmos/planning/forge-gate2-decision-packet.md` states, for each of the seven items, the measured facts, the options with consequences and the one-way-door nature; its facts table is generated from the package manifests and the bundle manifest with `--check`. Two non-decisions ship as hygiene with a record: the root `package.json` gains `private:true` (it is publish-shaped today), and the 20.11.1 CI cell becomes a real proof (the portable E2E runs on Node 20.11.1 and 24). License fields, publish flags, `.mcpb`, OCI and the manifest-on-health field are described and proposed, never changed.
8. **Sprint 194 and 195 rules stay in force.** An input property that does nothing does not exist; every changed description or schema has a boundary spec and the tool ledger re-derives with all 19 advertised tools at product-reality tier; registries, ledgers and generated docs are generated, never hand-edited; goldens move only as declared movers with BEFORE/AFTER receipts; verifiers pin recorded heads (`#565`); pre-freeze verifier pass (`#574`); one five-suite capture under `#1833` (two attempts, decision receipt for a third); mover derivation and the auditor use `-z` path output; pace rule: no per-mission captures, no critic, no new closeout apparatus.
