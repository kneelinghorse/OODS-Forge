## 2. Measured at the base (`04182b116`, 2026-09-15; direct reads, file:line)

**The protocol (spec 2026-01-26, folded into the 2026-07-28 extensions framework).** A UI resource has a `ui://` URI and the MIME type `text/html;profile=mcp-app`; a tool points at it with `_meta.ui.resourceUri`; the host and the server opt in bilaterally through `capabilities.extensions["io.modelcontextprotocol/ui"]` (the client lists `mimeTypes`); the host renders the HTML in a double iframe (sandbox proxy on its own origin, inner `srcdoc` frame) and pushes the tool result to the app (`ui/notifications/tool-result`, with `structuredContent`, which is not added to the model's context); the app calls `tools/call` and `resources/read` through the host, posts `ui/message` into the conversation, `ui/update-model-context`, `ui/request-display-mode` (`inline` | `fullscreen`), and receives `ui/notifications/host-context-changed` (theme, `containerDimensions`, `displayMode`). **The default CSP when the resource declares none is `default-src 'none'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; media-src 'self' data:; connect-src 'none'`**: inline scripts run, `blob:`, `data:` scripts and `eval` do not, and nothing loads from the network unless the resource's `_meta.ui.csp` names the origin (`resourceDomains`, `connectDomains`, `frameDomains`). No resource size limit is specified; hosts MAY prefetch the resource. The build guide bundles the whole app into one HTML file for this reason.

Claude Desktop renders apps from a local stdio server when **Developer Mode** is on, and caches UI resources by URI until "Reload MCP Configuration" (community server README, verified as the only documented local path; the official build guide tests through a tunnelled remote connector). ## 3. Settled decisions (build from these; do not reopen)

1. **Self-contained under the default CSP.** The app resource declares no CSP and works under the host default: one HTML file built at package build time with the host runtime inlined (React, ReactDOM, Vue, the foundation packages' dist, component-styles and token CSS); nothing loads from the network. Compiled artifacts reach the app through `resources/read` as text and are injected as inline scripts, so the host compile gains an `iife` mode whose externals bind to the inlined runtime's globals (React and Vue shared with the shell). The localhost preview host is never referenced from inside the sandbox. This is the only design that renders identically in every host without depending on a host's localhost, mixed-content or private-network policy.
2. **The adapter speaks the protocol itself**, with the SDK it has: `resources` capability with `resources/list` and `resources/read`; the `io.modelcontextprotocol/ui` extension advertised, and `_meta.ui.resourceUri` set on `design_preview` when the client negotiated the extension (the spec's SHOULD), so hosts without apps keep today's text result with the localhost URL (progressive enhancement). `design_preview` results gain `structuredContent` (the version identity, lineage, measurements, editable surface, resource URIs) beside the unchanged text content. `@modelcontextprotocol/ext-apps@1.7.5` is used only inside the built app (the `App` class) and in the reference-host harness (`app-bridge`); the runtime closure gains nothing server-side. The 19-tool `tools/list` and the initialize exchange the install proof asserts change only by the new capabilities, attributed.
3. **Resource URIs.** `ui://oods-forge/preview/<build revision>/app.html` is the shell (listed; the revision in the path defeats host caching across updates); `ui://oods-forge/compositions/<id>/<n>/<framework>.js` and `.css` are the compiled artifact and its styles (readable, not listed). The adapter serves the shell from `packages/mcp-bridge/dist/preview-app/` and the modules from the standalone host it starts lazily on the first module read.
4. **The reference host is the local gate.** A Chromium harness built on the SDK's `app-bridge` (double iframe, the default CSP, the sandbox proxy on its own 127.0.0.1 origin) drives the real adapter over stdio through a small relay, negotiates the extension, calls `design_preview`, and asserts the inner frame mounted the running app with zero console errors and zero `securitypolicyviolation` events, in both frameworks, brands A/B, themes light/dark/hc and the host's container widths. Every conversation feature is proven there. It is the CI stand-in; the five-suite capture stays the sprint capture.
5. **The app is the same surface as the browser page.** Lineage, measurement panel, brand/theme/width switches, the four edits, side by side with what-changed, reused from the Sprint 201 renderers compiled for the browser; the host theme sets the initial theme; container dimensions set the width; `fullscreen` is requested for compare.
6. **Accept and request changes are conversation acts with records.** `design.preview action:"accept"` records the accepted version on the composition (`accepted.json`: version, head, the measurements snapshot, when; a later accept supersedes with lineage), shown in `versions` and on both the app and the browser page; "request changes" sends `ui/message` into the conversation naming the composition, version and the requested change, and `ui/update-model-context` carries the accepted version's summary so the agent knows what stands. The schema is never hand-edited: a request is a message, an edit is a re-composition (`#2097`).
7. **From the bundle, into the real hosts.** `install.md` gains the in-conversation path: register the adapter directly in Claude Desktop (Developer Mode on; "Reload MCP Configuration" after an update) and in Cursor, beside any hub entry; `portable:assemble --final` and `portable:e2e` exercise `resources/list`, `resources/read` and a `design_preview` call with the extension negotiated from the extracted archive; the Linux container repeats it. The Claude Desktop and Cursor renders are the roadmap exit and are recorded when Derek runs them (the adapter logs to stderr which client negotiated the extension, so a real session leaves a receipt); they are never staged by the builder.
8. **The carries close first (m01), at the producer, receipted before and after**: placed-chart titles move out of the SVG into the figure heading; the generated shell gets landmarks and one heading so the three axe findings go to zero; the composer stops offering a tab slot a candidate `code.generate` refuses; a brand or theme switch shows the placed chart rendered and certified for that scope. Every pin that moves is appended once to the Sprint 202 golden ledger.
