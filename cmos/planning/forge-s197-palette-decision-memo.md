## 3. Settled decisions (build from these; do not reopen)

1. **Every semantic token name is frozen.** No key under `themes/*`, `brands/*` semantic aliases, `aliases/brand-*.json` or `viz-scales.json` is added, removed or renamed; only reference and brand values move. A contract test pins the semantic key set (light, dark, hc; A and B; viz) before and after. TraceLab's Tailwind mapping and the generated apps must need zero code edits.
2. **The reference layer is generated, never hand-edited.** A palette generator (`scripts/tokens/generate-palette.ts`, with a JSON-schema'd seed file under `packages/tokens/src/palette/`) produces `color.brand.json`, `color.neutral.json`, `color.status.json` and the brand base/dark files from seeds; the seed file is the only place a human names a hue or a chroma peak; `--check` fails when the generated files drift from the seeds. Existing step names keep their names; a full 50–950 ladder may be added as reference steps.
3. **One hue per ramp, monotonic lightness, mid-peak chroma.** Neutrals on one slightly cool hue near 265 with a chroma envelope rising from about 0.002 at 0/50 to about 0.02 at 600–800 and easing back. Brand A light surfaces are neutral (no beige tint under cool text). Accent gets a real hue distinct from primary. Each status family sits on one hue; only lightness and chroma move between surface, border, icon and text.
4. **Dark is designed as its own set, not an inversion.** Near-neutral canvas ladder with chroma under about 0.012, four or five elevation steps at even ΔL, accents lightened and de-chromatized so they sit on dark without bloom. Borrow the structure of Primer's dark and dark-dimmed sets, not their values. The generated app shell takes `data-theme` from compose preferences the way dashboard HTML already does (`#1860` item 3).
5. **The high-contrast paint scope is decided here, rendered in Sprint 199.** The `hc` token scope gains a complete, declared value for every paint role the chart renderer and components emit under `data-theme="hc"` (categorical slots, sequential and diverging steps, axis, grid, label, tooltip, legend, focus), using CSS system-color keywords where a role maps to one and declared literals elsewhere, so no type paints an undeclared color (OODS-V165). Sprint 199 renders the nine deferred types against this scope; this sprint proves the scope is complete by census, not by pixels.
6. **Chart colors derive from the new hue wheel.** Six categorical slots for light and for dark, evenly spaced hues, pairwise ΔE00 ≥ 12 under the three Machado color-vision-deficiency simulations (target; the clean line 10 is the floor and a caution pass is not acceptable), each ≥ 3:1 against its own canvas (Role-C), all above the 0.045 chroma floor, none colliding with the brand or accent hue. Sequential nine steps in gamut with mid-peak chroma; diverging eleven steps symmetric in both lightness and chroma; dark sequential and diverging sets added in `brands/*/dark.json`. If 12 is unreachable with Role-C intact, the measured ceiling is pinned with the reason and must still be ≥ 10.
7. **Brand B is a brand-seam demonstration, not a second design.** It is derived mechanically from one different seed hue through the same generator; it keeps its files and the `data-brand='B'` path; it cannot drift by hand.
8. **The guardrails gate the coherence, and the current palette must fail them first.** `relative-color.csv` and the two validators gain checks for ramp monotonicity, per-family hue drift, neutral hue drift, chroma-curve shape, gamut, and dark-scope coverage for sequential/diverging. m01 runs them against the unchanged palette and retains the red receipts: that is the objective statement that the current palette is bad.
9. **One golden migration, under the Sprint 195 m05 procedure.** Baseline before any value moves; attribute every moved golden by file and token BEFORE any capture (`#543`); bounded `--update` commands with `--coverage.enabled=false`; before/after SHA for every entry; historical matrix rows superseded by class and reason, never re-baked silently. Viz golden specs are expected red from m02 through m04 and green after m05; nothing is captured in between.
10. **"Better" is proven by looking, and TraceLab is never written to from Forge.** Side-by-side renders (old versus new, light and dark) of the generated Subscription and Organization screens and three TraceLab pages, produced from a throwaway copy of TraceLab's frontend fed the new tarballs; the re-pin (tarballs, provenance JSON, exact command) is prepared under Forge receipts and applied in TraceLab's own repo by that project. An independent reviewer inspects the sheets.
11. **Program rules stay in force.** No hand-edited generated file; measure before you claim; every schema or description change carries a boundary spec; one five-suite capture at close under `#1833`; `builderSelfCertified:false`; independent review in a separate session; no consumer notices of any kind (`#1979`).
12. **The type/spacing/radius/elevation/focus pass is a descope rung, not a promise.** It ships only if m01–m06 finish; otherwise it carries as written in `near.md` §5.
