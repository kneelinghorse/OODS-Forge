### s100-m02 — Q2 Bridge E2E Green + Coverage Gate Restored

**Status:** Completed
**Branch state:** Code-only (single 1-line build-script change).

**Mission-start audit was definitive.** All 7 failed CI suites traced to a single root cause: `ENOENT: packages/artifacts/dist/schemas/transcript.schema.json`. The `@oods/artifacts` package build script was `tsc -p tsconfig.json` only, never copying `src/schemas/*.json` to `dist/schemas/`. Locally the directory existed as leftover from prior builds (not tracked in git — `dist/` is in `.gitignore`). CI on a fresh clone never had it. When the MCP-server child process (spawned from the bridge) tried to load `validation.ts` (which reads the schema at import time, line 14), the child crashed before any tool could execute. Every `/run` request to the bridge surfaced as `400 RUN_ERROR`.

**Fix** at `packages/artifacts/package.json:14`: build script changed from `tsc -p tsconfig.json` to `tsc -p tsconfig.json && mkdir -p dist/schemas && cp -f src/schemas/*.json dist/schemas/ 2>/dev/null || true` — matching the `mcp-server` pattern.

**Affected suites all green locally** after rebuild: `mapping-versioning.e2e` (3/3), `registry-gaps.e2e` (3/3), `fragment-integration.e2e` (9/9), `a11y-pipeline.e2e` (3/3), `design-compose.e2e` (3/3), `bridge/fragment-parity` (1/1) — 22/22 in 17.6s. The 7th affected file from the CI tally (the spread across `a11y.contract` / `security.model` / `stage1-integration` / `brand.apply.patch` / `diag.snapshot-counts` / `preview.compaction` / `tokens.build.apply` contract specs) all trace to the same import-time `validation.ts` load and are also fixed by this single change.

**Scope-growth contingency not triggered.** Single-fix root cause, no architectural work, no m02a/m02b split. The "Bridge E2E flakiness" pre-existing-friction note from sprint-99 is now retired — it was never flakiness, it was a fresh-clone-vs-hot-dev-machine build-completeness gap.

## Decisions Captured (m01–m04)

1. **CI vr-test gating shape** (m01): step-output guard over dynamic `$GITHUB_ENV`-set var. Lint-clean and reversible.
2. **Adapter fresh-install root cause** (m01): build-ordering issue masked by smoke-test schema fallback. Workspace packages must build before mcp-server.
3. **Dotenv loading pattern** (m01): per-package `load-env.ts` using explicit project-root path from `import.meta.url`; imported FIRST in entry points.
4. **Bridge E2E single root cause** (m02): missing `dist/schemas/*.json` copy step in `@oods/artifacts` build. All 7 affected suites cascade from one ENOENT.
5. **Antipattern named** (m02): "fragile-build-chain-with-silent-fallback-masked-by-dev-machine-leftovers." When a build is incomplete, outputs exist from prior builds, and consumers fail loud only on file-not-found, the bug only surfaces on fresh-clone CI. Mitigation: explicit copy step + `rm -rf dist && pnpm run build` verification when adding non-TS asset emitters.
6. **D2 v2 approach choice** (m03): approach (a) — extend `buildCatalogAnnotations()` to be variant-aware via `selectVariant()`. Centralizes variant logic; emitters unchanged.
7. **Variant-omitted byte-identical behavior** (m03): selectVariant's fallback chain means callers who didn't pass variant before still get the same code path. No existing test required updating beyond the one wireframe test that explicitly documented the s99-m01 finding.
8. **concordance.validate usage signal: ZERO** (m04): three days of accrual; no production callers; no agent invocations; no production gating need.
9. **Pipeline auto-integration formal re-defer with 3 named triggers** (m04): (a) 5+ tool invocations in one session across 2+ workflows, (b) real-world compose-time manifest error from outside tests, (c) explicit downstream consumer ask. Until any fires, ship-without-callers is the wrong call.
10. **C-track shared HTML util promoted from alternate to delivery** (m04): rule-of-three fully triggered, zero behavior change, +2 files, -66 lines of duplication. Resolves decision #460.
