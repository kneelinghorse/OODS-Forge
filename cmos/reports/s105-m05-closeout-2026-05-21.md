### s105-m01 — I3 telemetry scaffolding (OTLP)

First push on the Integration track (I3) since the mission graph was authored. Env-var-gated OpenTelemetry SDK with OTLP/HTTP exporter; **zero runtime overhead and zero import-time cost when telemetry is unset** beyond the no-op tracer from `@opentelemetry/api`.

**Mission-start audit captured as CMOS decision BEFORE any telemetry code per Rule 1 (n=7 of pattern at time of mission start).** Five axes resolved on IMPLEMENTATION path.

- `packages/mcp-server/src/telemetry/otel.ts` — hybrid load pattern: `@opentelemetry/api` always-loaded (no-op tracer when SDK absent), `@opentelemetry/sdk-trace-node` + `@opentelemetry/exporter-trace-otlp-http` dynamic-imported only when `OODS_OTLP_ENDPOINT` is set.
- Dispatcher span at `src/index.ts` wraps every MCP tool call with span name `forge.tool.<tool_name>` + `SpanKind.SERVER`. Span attributes follow OTel `rpc.*` semantic conventions (`rpc.system="oods-forge"`, `rpc.service="mcp-server"`, `rpc.method=<tool>`) plus custom `oods.*` (role, request_id, ajv_failed, ajv_layer, error_code, ajv_error_count).
- SIGTERM/SIGINT drain hook flushes the BatchSpanProcessor before exit so spans don't get dropped on graceful shutdown.
- Auto-detects `OTEL_SERVICE_NAME` (standard OTel env var) with fallback to `OODS_OTLP_SERVICE_NAME` then `oods-forge-mcp-server`. `OODS_OTLP_HEADERS` supports comma-separated `key=value` pairs (Bearer auth etc.).
- 16 unit tests via `InMemorySpanExporter` (initTelemetry/shutdownTelemetry contract, startToolSpan attribute mapping, recordSpanError + recordAjvFailure semantics).
- 3 direct OTel deps added per mission-spec minimum — api + sdk-trace-node + exporter-trace-otlp-http. NO auto-instrumentations.
- `agents.md` documents the env-var gate above the existing scale-tier section.
- Total m01: **+1 src file / +1 test file / +16 active tests** + 4 modified.
