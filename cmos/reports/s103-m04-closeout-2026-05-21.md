### s103-m03 — A2UI Image custom-catalog extension

Closed the OODS-A2UI-IMAGE-FALLBACK gap from sprint-102 m03 (decision #533). Image-kind slots in the Object Catalog now emit A2UI `Image` components with the URL bound via DataBinding instead of falling back to Text with a per-occurrence fail-loud warning.

**Rule 12 + Rule 1 honesty note:** The mission spec referenced an A2UI `acceptsInlineCatalogs:true` extension point for declaring the custom catalog inline in the message stream. That field does NOT exist in vendored A2UI v0.9 schemas (`server_to_client.json` `CreateSurfaceMessage` has `additionalProperties: false` and no inline-catalog payload). Rather than fake the extension point or break v0.9 strict validation, implementation chose the spec-compliant alternative: a Forge-published companion catalog file referenced by stable catalogId. Captured as a CMOS decision.

- `packages/mcp-server/src/a2ui/contracts/v0_9/catalogs/forge/catalog.json` — new Forge custom catalog. Strict superset of minimal (Text/Row/Column/Button/TextField) plus Image. Image: `url=DynamicString` (required), `alt=DynamicString` (optional), `fit=enum` (optional). Canonical `catalogId = oods-forge:catalog/v1` published as `FORGE_CATALOG_ID` export.
- `a2ui-runtime-emitter.ts` updated — added `A2uiImageComponent` to the discriminated union; image-kind slot path now emits Image instead of Text+warning; `meta.catalogProfile` flipped from `'minimal'` to `'forge'`; `projectSlot()` simplified (entityUrn + warnings params dropped after warning removal).
- Existing Q3 test `test/e2e/a2ui-runtime-q3.e2e.spec.ts` — AJV setup registers `forgeCatalogSchema` under `https://a2ui.org/specification/v0_9/catalog.json` (replacing `minimalCatalogSchema`); cross-fixture image-fallback assertion inverted to assert NO warning + Image emission. **98 Q3 cases preserved in count; behavior assertion flipped per success criterion.**
- New focused test `test/e2e/a2ui-image-q3.e2e.spec.ts` — 24 tests asserting catalog file structure (5 minimal + Image; 6 entries in `anyComponent.oneOf`; `catalogId` matches `FORGE_CATALOG_ID`); Image emission against article/author/comment/content-pack fixtures (no FALLBACK warning, ≥1 Image per fixture, `url` is DataBinding, `alt` populated, AJV-validates against Forge#components/Image, non-image slot names don't classify as image).
- Per-entity `catalogId` pattern (`oods-forge:<urn>`) preserved from s102-m03 — all `oods-forge:*` IDs are now understood to reference the same Forge catalog vocabulary (`oods-forge:catalog/v1`).
