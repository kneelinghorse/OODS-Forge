**Two findings surfaced and fixed in-mission:**

1. **Railway cold-start exceeded the 5s blocking timeout.** First validate call timed out at exactly 5009ms with `ConcordanceError: operation was aborted`; subsequent calls in the same run completed in 100-300ms (service warmed). Fix: `beforeAll()` in the smoke spec sets `CONCORDANCE_TIMEOUT_MS_BLOCKING=15000` when unset. Smoke-only scope — production codegen 5s default unchanged. Carry-forward: if production codegen sees intermittent timeouts from cold-starts in real usage, revisit the default deliberately.

2. **Strict byte-equal G3 was over-strict.** Concordance's Pydantic GET response materializes optional fields with null/empty defaults: `element` gains `{object:null, action:null}`, `semantics` gains `{synonyms:[]}`, each `relationships.edges[]` gains `{confidence:null, via:null, reason:null, evidence_refs:[], captured_at:null, metadata:{}}`. None of these are mutations of Forge-provided values — they are Python-side representations of "absent." The real D1 contract ("concordance preserves the kernel verbatim") is best tested as deep-subset equality. Fix: new `diffKernel()` helper at the top of the spec asserts every Forge-declared key/value is present unchanged in concordance's response; concordance may add keys, but only if the added value is an optional-default sentinel (null / `[]` / `{}`). G3 test renamed to "G3 hosted canonical-kernel: every Forge-declared value preserved verbatim".

**Idempotency:** subscription URN is stable; every re-run re-POSTs the same entity. No ephemeral URNs, no concordance pollution.

**Auth hygiene maintained:** key read from `process.env` at request time, never logged, never echoed in error messages, never persisted to git/CMOS/snapshots.

## Decisions Made This Sprint

1. **Sprint-98 shape locked (2026-05-16)** — N=5 with closeout: m01 D2 runPreEmit, m02 C1 boxes-and-arrows + Q3, m03 concordance.validate tool, m04 I1 live + G3 byte-equal, m05 closeout.
2. **m02 deliverable: HTML/CSS over SVG (2026-05-16)** — boxes-and-arrows emitter ships as HTML/CSS, not SVG. Reuses existing tooling, more amenable to future interactive hookup. SVG export remains a lower-priority future-iteration possibility.
3. **m03 surface: agent-callable only (2026-05-16)** — concordance.validate exposed as MCP tool; NOT auto-baked into pipeline. Pipeline auto-integration deferred to a future sprint once tool surface accumulates real usage.
4. **Synthesized tree shape for SemanticEntity input (m01)** — root UiElement uses `entity.element.type` as component name, carries `data-entity-urn` + `data-element-name`; slot children use `component='Slot'` with `data-slot-name` + `data-field`. Stable enough for v0.1 boxes-and-arrows consumption; revisable when subsequent emitters reveal needs.
5. **Variant resolution before pre-emit (m01)** — `runPreEmit(entity, { variant })` picks the matching `projection_variants[]` entry; missing variant falls back to `oods.render`; absent render falls back to first variant. Single tree in, single render out. Multi-variant projection is the caller's job.
6. **PreEmitContext kept as function-shaped abstraction (m01)** — no typed intermediate IR with persistence/schema yet. Per D2 deferred-formalization rule, IR promotion waits for either two emitters needing the same structured output projection (A2UI + structured-data export is the most likely trigger) OR a non-Forge consumer wanting a custom renderer.
7. **Boxes-and-arrows visual language for v0.1 (m02)** — entity = solid border box with role-colored border + colored role chip header; relationship = dashed-border row with Unicode arrow glyph and inline via/weight labels; cross-manifest target URNs highlighted yellow with `data-external="true"`. CSS-only. Semantic data-attributes are the durable contract; visual is reasonable default.
8. **External Q3 fixture is 3-entity all-internal billing manifest (m02)** — cleanly separates internal-vs-external relationship-target paths across the 4 gate fixtures (subscription already exercises external-target path).
9. **concordance.validate error namespace OODS-CV-001..012 (m03)** — handler-level guards use unregistered codes that flow through `createError`'s fallback (category=`server_error`, retryable=false, incident_id). Can be promoted to the registered family later without changing call sites.
10. **concordance.validate policy profile (m03)** — read-only, designer+maintainer, 30s timeout, 60/min, concurrency=4. Matches the repl.validate / map.list / schema.list profile.
11. **Concordance preserves the kernel verbatim (m04)** — D1 contract confirmed empirically. The diffKernel() deep-subset semantic in `test/integration/concordance-i1-smoke.spec.ts` is the durable executable form; future fixtures added to the G3 step by URN don't require helper changes.
12. **Smoke-test cold-start timeout policy (m04)** — 15s for the I1 hosted smoke (set via beforeAll). Production codegen default stays 5s. Rationale: Railway cold-starts hit smoke runs but warm production keeps the service hot.
