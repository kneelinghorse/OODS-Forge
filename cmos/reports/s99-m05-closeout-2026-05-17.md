### s99-m02 — I3 Client Retry Logic (bounded exp-backoff on 429/5xx)

**Status:** Completed
**Branch state:** Code-only.

**Deliverables:**
- New `packages/mcp-server/src/concordance/retry.ts`. Exports `DEFAULT_RETRY_POLICY` (maxRetries=3, baseDelay=500ms, maxDelayPerRetry=4000ms, totalWaitCap=8000ms), `RetryPolicy` / `RetryClock` / `RetryLogger` interfaces, `isRetryableStatus()`, `parseRetryAfterMs()` (handles RFC 7231 delta-seconds AND HTTP-date forms; rejects non-alpha numerics like "12.5" that Date.parse would otherwise coerce), `computeBackoffDelay()` (full-jitter, Brooker-style), `computeRetryDelay()` (Retry-After overrides exp-backoff), `exceedsBudget()`.
- `client.executeRequest()` refactored into a loop with `runOnce()` returning a 3-arm outcome (`success` | `mapped-error` | `network-error`). Retry is opt-in per call via `RequestOptions.retry`. Retry-After parsed BEFORE the response body so 422 detail.errors[] still flows through the normal mapping path on non-retried failures.
- Per-retry log event shape: `{ attempt, delayMs, status, requestId, retryAfterUsed }`. Default sink is `console.info` at the same verbosity as I1-smoke diagnostic prints — production deployments can swap in a structured-logger sink without touching the orchestration.
- Budget guard: planned delay must fit within both `(timeoutMsBlocking - elapsedMs)` AND `(totalWaitCapMs - cumulativeSleepMs)`. If either is exceeded, the retry chain aborts and the original mapped error surfaces.
- 20 helper unit tests at `src/concordance/retry.test.ts`: `isRetryableStatus` (429, all 5xx, non-retryable 4xx, 2xx/3xx, out-of-spec 6xx+); `parseRetryAfterMs` (delta-seconds, HTTP-date relative to nowMs, past-date clamp-to-zero, null / empty / malformed / "12.5"); `computeBackoffDelay` (invalid attempts → 0, full-jitter ceiling, per-retry cap, rng=0 floor); `computeRetryDelay` (Retry-After delta + HTTP-date override, fallback when absent, fallback when malformed); `exceedsBudget` (timeout + cumulative caps + happy path).
- 11 new client integration tests at `src/concordance/client.test.ts`: 429 → 200 success with 1 sleep + 1 log event; 429 × 4 surfaces final error after maxRetries exhausted (3 sleeps, 3 log events); 503 → 200 success; 500 × 4 surfaces final error; Retry-After: 2 → 2000ms wait (Retry-After overrides exp-backoff); Retry-After: 1 on 503 → 1000ms wait; 5 non-retry-4xx codes (400 / 401 / 403 / 404 / 422) surface immediately without retry attempts (one assertion per code); budget guard with aggressive clock aborts before sleeping; per-attempt log event shape pinned to `{attempt, delayMs, status, requestId, retryAfterUsed}`; success path is transparent (0 sleeps, 0 logger events when fetch returns 200 first try).

**Live-smoke exercise NOT executed in-session:** `CONCORDANCE_API_KEY` not in env. The success-path-transparency test demonstrates retry is invisible on first-try 200, so I1 round-trip behavior is unchanged under no-failure conditions. User to re-run `RUN_HOSTED_SMOKE=1` at convenience.

## Decisions Made This Sprint

The full decision register including planning-side decisions is reachable via `cmos_decisions(action="list", sprintId="sprint-99")`. Implementation-side highlights:

1. **D2 abstraction generalization validated empirically (m01)** — function-shaped `PreEmitContext` (decision #435) holds across C1 boxes-and-arrows AND C2 wireframe with completely different visual fidelities, consumed unchanged. The IR-memo trigger remains queued for a case where two emitters need the SAME structured output projection (most likely A2UI runtime + structured-data export per decision #442).
2. **D2 generalization finding NOT silently fixed (m01)** — `CatalogAnnotations.slots` is variant-blind. Two clean resolutions named for a future D2 v2; not load-bearing for current emitters; becomes load-bearing when multi-variant projection becomes a real use case.
3. **Wireframe visual language v0.1 (m01)** — light-gray solid-border entity boxes; dashed slot rectangles; no role color, no traits, no relationships; `data-fidelity="wireframe"` body marker for future editor dispatch.
4. **Full-jitter exp-backoff over equal-jitter / decorrelated (m02)** — simplest scheme; bounded by per-retry cap + cumulative-sleep cap + budget guard. Decorrelated jitter is a better choice when many clients share rate-limit budget; single-tenant validate-path call site doesn't warrant the complexity.
5. **Retry-After HTTP-date parser stricter than RFC 7231 (m02)** — refuses values that contain no alpha characters even if `Date.parse()` would coerce them. Falls through to exp-backoff for malformed inputs rather than honoring a bogus delay derived from Node's lenient date parser. Pinned by tests.
6. **Retry surface scope promoted v0.1 → v0.2 in m03** — `validateManifestRemote` only (m02) → `validateManifestRemote` + `submitManifest` + `getEntity` (m03). The G3 multi-fixture round-trip is the real burst-load usage signal that m02's closeout documented as the broader-rollout gate.
7. **Decision #440 (canonical-kernel D1 contract) confirmed across full 4-fixture surface (m03)** — `diffKernel()` helper required zero modification, validating the s98-m04 design intent that future fixtures add by URN without contract-helper churn. Live confirmation gated on user re-running RUN_HOSTED_SMOKE=1.
8. **Missing `oods.confidence_decomposition` classifies as 'unknown' tier (m04)** — gray badge, score placeholder, flagged for review. Adds a fourth tier beyond the spec's high/medium/low triad. Confirmed by production fixtures: user / subscription / billing-account / payment-method all lack the field today and would otherwise vanish from review surfaces. Refusing to render them or silently treating them as 'medium' would be worse UX than honestly surfacing the missing-data signal.
9. **REVIEW NEEDED threshold uses strictly-less-than (m04)** — an entity exactly at threshold is acceptable; `needsReview(0.7, 0.7) === false`. Reviewers can set threshold=score to shrink the review surface to entities strictly below that score. The alternative (≤) would force boundary scores into review unnecessarily.
10. **C3 reads `oods.confidence_decomposition` directly from entity (m04)** — rather than via `ctx.catalog.confidenceDecomposition` which pre-emit also surfaces. Both carry the same value; reading from source makes the renderer's data dependency on the F1 field explicit and survives a future refactor that might drop the field from CatalogAnnotations.
11. **Rule-of-three for HTML escape helpers triggered but not actioned (m04)** — boxes-arrows, wireframe, AND review emitters now duplicate `escapeHtml` + `attr` + `dataAttr`. Shared util extraction queued for sprint-100 to keep C3's scope tight.
12. **Rollup-regate `generatedAt` source-fixed (m05)** — third consecutive sprint with this friction; per decision #449, fix at source rather than another one-off revert. Recommendation (a) held: deterministic `'2026-04-17T00:00:00.000Z'` anchored to the s94 closeout date already encoded in the filename. Friction pattern ends here.
